Loop. A real newSeason build starts the season. Every Sunday at 21:00 the harness records the week's activities, writes the modelled FTP and threshold pace as Garmin-style estimates, and runs a real plan refresh with includeTomorrow. The next week is read from nextWeek, then simulated day by day. Sundays continue until the season ends.

Activities. Each prescribed session is converted into an imported activity with concrete duration, distance, elevation, average and normalized power, average heart rate and pace. Cycling and running TSS therefore comes from measured power or pace, not from free text. A race day is simulated from the athlete's modelled ability on that morning.

Progression. Ability is a function of chronic training load (CTL, 42-day EWMA): the athlete regains the gap to the prior peak with diminishing returns and never exceeds it in this model. The model is a simulation assumption, not app logic.

Feasibility. The report makes an independent numeric check beside the coach's own words. The half is predicted from threshold pace (half pace = 1.04 × threshold, 1% taper). The gravel race uses a steady-state speed/power model (93 kg system mass, CdA 0.385, Crr 0.0055, 97% drivetrain, 3:10 target). A target is treated as met within a 1% modelling tolerance. The solo and group cases are reported separately.

Weather and daylight are a deterministic Trondheim-like seasonal approximation rather than a live provider call, so the season is reproducible. The app's real prompt, plan validation, period reviews and stored-plan pipeline are otherwise used unchanged.

Caveats

  • The progression curve and the race models are explicit assumptions, not the app's own prediction. They are anchored to the athlete's stated history but a real athlete's response varies.
  • Every session is assumed completed exactly as prescribed. The second test changes only how often the athlete trains, not how well a session is executed.
  • The gravel model is steady-state and uses average grade; it is not a lap-by-lap simulation and does not model wind, surface changes or group tactics beyond the group-power factor.
  • Weather and daylight are synthetic and deterministic. The coach's real prompt, plan validation, reviews and storage path are unchanged.
  • One run per scenario. The model is stochastic, so a repeat would differ in detail even with the same athlete.
