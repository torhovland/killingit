# Spec: Unit-test coverage and thresholds

- **Status:** Accepted (implemented)
- **Date:** 2026-11-11
- **Related:** `AGENTS.md` (Development Methodology), issue #166,
  `docs/specs/database-integration-tests.md`, `docs/specs/e2e-tests.md`.

## Goal

Make unit coverage visible on every pull request and fail CI when it drops
below the recorded baseline, so a new module without tests and a test that no
longer exercises its code both show up before merge. The thresholds ratchet up:
they are set from the measured baseline and are raised as coverage improves.

## Scope

### In scope

1. `bun run test:coverage` runs the existing unit suites under Bun's LCOV
   reporter, without changing what the suites test.
2. A per-package threshold for line and function coverage, enforced from the
   merged report.
3. A merged `coverage/lcov.info` report, and a markdown table in the CI job
   summary.
4. A build artifact carrying the merged report on every run.

### Out of scope

- Coverage for the integration and end-to-end suites. They run in their own CI
  jobs and are measured by their assertions, not by line coverage.
- Per-file thresholds. A single aggregate per package is the ratchet; one
  low-coverage module cannot fail a pull request on its own.
- Coverage of a source file that no test loads. Bun only instruments files a
  test imports, so such a file is absent from the denominator until the first
  test reaches it.

## Behaviour

### Command

`bun run test:coverage` runs, in order:

1. `bun test scripts`, the development-tooling suite. It runs for parity with
   `bun run test` but is not measured.
2. `bun test src` in `apps/api`.
3. `bun test src pwa notices` in `apps/web`.
4. `bun test` in `packages/shared`.
5. `bun test src` in `tools/benchmark`.

Each application suite runs with `--coverage --coverage-reporter=lcov` and
writes its raw report to `coverage/raw/<package>/lcov.info`. The script
normalises every source path to a repository-relative path, keeps only files
owned by the package, and merges the result into `coverage/lcov.info`.
`coverage/` is gitignored.

### Baseline

Measured on 2026-11-12 with Bun 1.4.4, the version pinned in the CI test job.
Bun changes how many executable lines and functions it counts between releases,
so moving the pin also means re-measuring the baseline. The threshold is the
measured value floored to a whole percent, leaving a small margin for harmless
variation. Both lines and functions are checked.

| Package   | Lines measured | Line threshold | Functions measured | Function threshold |
| --------- | -------------- | -------------- | ------------------ | ------------------ |
| api       | 72.97%         | 72.0%          | 77.60%             | 77.0%              |
| web       | 77.75%         | 77.0%          | 72.61%             | 72.0%              |
| shared    | 95.92%         | 95.0%          | 87.64%             | 86.0%              |
| benchmark | 90.48%         | 90.0%          | 100.00%            | 100.0%             |

The api floor was 73.0% of lines and 78.0% of functions until the benchmark
harness and its tests moved to `tools/benchmark` (ADR 0032). The well-covered
`promptBenchmark` module left the api denominator while its tests kept running
in the benchmark group, so the remaining server code re-measured at 72.97% of
lines and 77.60% of functions.

The baseline lives in `COVERAGE_GROUPS` in `scripts/coverage.ts`. When coverage
improves, raise the matching threshold in the same pull request. Lowering a
threshold needs a documented reason, because it silently accepts lost tests.

### Excluded paths

- `apps/api/src/llm/promptRules.ts` — shared prompt text. Its tests assert the
  prompt contracts, and counting prose as executable lines says nothing about
  test quality.
- `apps/api/drizzle/` — migrations and metadata generated by drizzle-kit. They
  are exercised by the integration suite, not by unit tests.

The exclusion list lives beside the groups in `scripts/coverage.ts`. Test
files are already excluded by Bun's `coverageSkipTestFiles` default.

### CI

The `test` job pins Bun to the version the baseline was measured with, runs
`bun run test:coverage` instead of `bun run test`, and fails when any package is
below its threshold. The script appends the coverage table to
`$GITHUB_STEP_SUMMARY`, so the result is visible on every pull request without
another service.

The job then attaches `coverage/lcov.info` as the `coverage-lcov` build
artifact, so the raw report is available to download from the run. If the
repository is later activated on Codecov, an upload step can consume the same
file without changing the baseline or the summary.

## Data-model and API impact

None. The check only reads test output.

## Acceptance criteria

- `bun run test:coverage` passes on the current `main` and prints one table with
  every package, its actual coverage, its threshold, and the total.
- Dropping below a line or function threshold exits non-zero with a message
  naming the package and metric.
- `coverage/lcov.info` contains repository-relative `SF:` paths, one record per
  file, and no excluded path.
- CI runs the coverage check in the `test` job and publishes the table in the
  job summary.
- `bun run test` remains the fast, database-free test command and does not
  write coverage output.
